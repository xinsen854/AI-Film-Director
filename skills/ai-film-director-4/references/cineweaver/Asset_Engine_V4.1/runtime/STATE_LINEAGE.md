# STATE LINEAGE

Persistent state follows:

# MASTER → STATE

A STATE must include:
- `inherits_from` master asset;
- state category;
- state start;
- state end or `ongoing`;
- source story fact;
- trigger cause;
- visible change;
- unchanged identity / structure facts;
- `compatible_with`;
- `conflicts_with`;
- reuse / persistent scope;
- image file/status if a reference board is necessary.

Valid persistent categories include:
- wardrobe;
- injury;
- wetness;
- dirt / contamination;
- transformation;
- location time/weather/damage/function state;
- prop open/closed/damaged/content state.

Do not create persistent STATE for:
- single-shot expression;
- temporary pose;
- one breath change;
- current Beat reaction;
- a one-line emotional delivery;
- trivial wrinkle or transient posture.

A state never becomes a duplicate master identity.

## Reference-board temporal isolation

- MASTER reference boards stay canonical / time-neutral. They must not visually pre-bake a future persistent change merely because that change will happen later in the story.
- A STATE reference board is a snapshot of the state valid from its own `state_start`; it must not combine future sibling STATE deltas into one convenience board.
- If an Information Ledger reveal is still protected, the currently callable MASTER / STATE image prompt must not contain its protected literal or an equivalent explicitly revealed detail.
- When a change occurs later inside the same scene, use a sufficiently precise `state_start` marker (for example SHxxx) rather than a broad scene label that would make the earlier beat ambiguous.
- This rule applies only to assets actually called by the current Member SH; it does not force every future asset to be stripped of its own valid future content.
