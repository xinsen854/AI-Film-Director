# Asset Prompt Contract

## 总原则

资产Prompt的目标是：**让后续模型反复得到“同一个人、同一个地方、同一个道具，以及它们正确的持续状态”。**

项目总资产数量不设上限。资产数量由故事和一致性需要决定。

## Reveal / 时间状态隔离

资产参考图不是故事全时间线展示板。任何会被当前 SHOT 当作媒体参考的 Canonical / STATE 图片Prompt，只能包含该参考在当前生效范围内已经允许可见的事实。

- Information Ledger 仍为 `HIDDEN / PARTIAL` 的 `protected_literals` 不得提前写进当前调用资产的图片Prompt；
- MASTER 必须保持时间中性，不得为了“一张图方便”混入以后才出现的持续状态；
- STATE 只描述自身 `state_start` 后已经生效的Delta，不得混入未来兄弟STATE的 `visible_change`；
- 一个道具存在“外观先出现、内部内容后Reveal”时，基础资产只建立前期可见外观；后Reveal内容用合法后续STATE或后续参考承担；
- 不要求把未被当前Member SH调用的所有资产做当前GU扫描，避免把工程隔离变成全库创作限制。

资产Prompt不要直接写成电影镜头Prompt；除非资产本身就是多视图板，否则不应该被单一摄影机角度绑死。

---

# 一、所有资产共同头部

每个Prompt先写清：

```text
【资产ID】
【资产名称】
【资产类型】人物 / 人物状态 / 场景 / 场景状态 / 道具 / 道具状态 / 群体 / TEXT_VOICE_ASSET
【用途】Canonical参考 / 多视图板 / 状态继承 / 关键细节
【项目年代与世界】
【制作媒介】
【整体写实/风格化程度】
【材质与色彩基准】
【必须保持不变】
【本资产允许变化】
```

不要写与这个资产无关的项目背景大段说明。

---

# 二、人物基础资产Prompt

```text
为同一人物建立生产级角色参考资产。

画面一：大型3/4面部身份近景，脸部略微转向，
完整展示稳定的面部结构、发型和身份标记。
眼睛具有自然眼神光。

画面二：正面完整身体参考，从颈部以下至脚部，
故意不显示头部。
清晰展示身体比例、肩宽、四肢比例、基础服装、
鞋、配饰及服装材质。

画面三：背面完整身体参考，
保持与正面完全一致的身体比例、发型轮廓、
服装结构、材质和颜色。

中性灰色背景，平坦均匀照明，
真实未经修饰的皮肤，清晰可见毛孔和自然肤色差异。
不使用戏剧化灯光，不使用电影镜头效果，
不使用胶片颗粒，不磨皮，不美颜，不添加文字。
所有画面表现同一个人物。
```

# 三、人物状态资产Prompt

开头明确：

```text
继承自：Axxx
上一状态：
状态开始剧情：
预计结束剧情：
```

然后只写Delta。

## 必须保持

- 脸；
- 身高与体型；
- 头发基础结构；
- 未被剧情改变的服装结构；
- 稳定身份标记。

## 允许变化

按状态类型写具体物理分布。

### 淋湿示例维度

- 头发哪里先湿；
- 水滴是否从发梢/下颌滴落；
- 肩、胸、背、袖口、裤腿的湿度层级；
- 布料吸水后的颜色、重量和贴体程度；
- 鞋面、裤脚是否沾水；
- 是否影响动作和握持。

### 伤势示例维度

- 精确部位；
- 肿胀/擦伤/包扎/渗血等可见程度；
- 动作限制；
- 哪只手/哪条腿不能正常发力；
- 后续状态是加重、稳定还是恢复。

### 换装示例维度

明确新服装每一件，并说明脸、身体、头发仍为同一人物。

# 四、场景基础资产Prompt

## 1. 空间身份

- 年代；
- 建筑类型；
- 尺度；
- 功能；
- 使用者；
- 长期磨损和生活痕迹。

## 2. 几何

明确：

- 房间/区域关系；
- 门；
- 窗；
- 走廊；
- 楼梯；
- 柱/墙/隔断；
- 固定大型家具；
- 主要设备；
- 人物可走路径；
- 不可穿越区域。

## 3. 材质

分别说明：

- 墙；
- 地；
- 顶；
- 门窗；
- 木/金属/玻璃/布料等；
- 旧化程度；
- 反射特性。

## 4. 光源

- 窗口方向；
- 顶灯/台灯/广告牌/设备屏幕等固定光源；
- 白天/夜晚的基础逻辑；
- 不要把某一场的临时戏剧光写死成场景永久属性。

## 5. 多视图板

根据空间复杂度选择：

- Master；
- Reverse；
- 关键功能区；
- 入口/出口方向；
- 重要关系位；
- 鸟瞰/平面。

多视图必须是同一地方，门窗和固定结构位置互相吻合。

---

# 五、场景状态Prompt

明确继承基础场景，不改变几何。

只写：

- 昼夜；
- 实际开灯/断电；
- 天气进入空间的程度；
- 水、烟、灰、破损、碎片；
- 门窗开闭/损坏；
- 群体长期占用；
- 设备运行；
- 其他持续状态。

必须写：

```text
固定墙体不变
门窗位置不变
大型固定物位置不变（除非剧情明确移动）
空间比例不变
```

---

# 六、道具Prompt

## 基础道具

- 尺寸；
- 比例；
- 结构；
- 材质；
- 表面处理；
- 磨损；
- 标志/文字（只有剧情必要时）；
- 可动部件；
- 开合/操作方式；
- 握持方式；
- 内容物；
- 技术年代；
- 多个关键视角。

## 状态道具

只改变：

- 开/关；
- 满/空；
- 完整/损坏；
- 洁净/污染；
- 有电/断电；
- 内容物；
- 其他剧情支持变化。

---

# 七、群体资产Prompt

只有群体需要保持稳定视觉逻辑时建立。

说明：

- 人数范围和密度；
- 年龄/体态分布；
- 统一服装/装备规则；
- 个体差异范围；
- 阵型或行为规律；
- 禁止同脸复制；
- 禁止所有人同姿态；
- 与场景尺度的关系。

---

# 八、负面约束只写真正必要的

不要堆几十条泛化negative prompt。

优先排除：

- 身份漂移；
- 额外肢体；
- 错误服装结构；
- 场景几何突变；
- 道具结构变化；
- 多视图人物被误生成为多人；
- 资产板文字/边框进入电影画面；
- 不符合年代/世界观的设计。

---

# 九、生成结果验收

实际生成后只接受：

- 身份一致；
- 结构一致；
- 状态继承正确；
- 多视图内部一致；
- 能继续作为视频参考使用。

不合格结果标记FAILED并说明原因，不得偷偷进入Canonical参考。


# 九、声音身份与生成文件

`V001...` 只保存稳定Voice Profile文本，不生成图片、视频或音频。视觉资产通过接受检查后按Registry的 `canonical_filename` 保存，格式为 `ID_中文名_类型或状态_Vxx.ext`；状态图必须显式继承母资产，不重新设计身份。
