# Contributing

Thank you for helping improve AFD's emotion-driven narrative and filmmaking workflow.

## Useful contributions

- A reproducible failure in an emotion handoff, scene state, storyboard or asset contract.
- A screenplay-based test that distinguishes emotional evidence from speculation.
- A validation test for continuity, locks, file formats or model constraints.
- A better model adapter backed by actual provider capabilities.
- An example that identifies limits or counterexamples—not just a positive showcase.

## Before opening a change

1. Describe the screenplay evidence, expected behavior and actual behavior.
2. State the affected stage and owner module.
3. Preserve the Forge story/emotion authority and AFD downstream boundaries.
4. Add a focused test when changing executable behavior.
5. Run the existing release validation, or report exactly which dependencies are unavailable.

Please do not submit private screenplays, access keys, personally identifying project documents or unlicensed media in an issue or pull request.

The default screenplay lock is human-reviewed. Never bypass approval or make external media-generation claims without an actual provider result.
